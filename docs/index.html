核心能力 架构 技术栈

CAPABILITIES

核心能力

八个可验证的工程深度点，全部有源码与文档对应。

01

混合检索

BM25 与 KNN 双路并行召回，RRF 融合排序，可选接入 gte-rerank 重排模型。

02

父子检索

small-to-big：命中小分块后自动扩展相邻大分块提供给模型，引用仍指向命中的小分块，精度与上下文兼得。

03

强制引用标注

回答句末携带 (来源#编号: 文件名 | 第X页)，可选逐句校验，无依据的引用会被标记。

04

文档冲突检测

向量化完成后异步扫描相似但数字、版本号、日期不一致的分块对，由管理员在后台人工裁决保留哪一篇。

05

离线评测框架

检索看 Recall@K 与 MRR，生成看 LLM-as-a-judge，支持人工抽检与评委一致率（Cohen's kappa），内置 50 条评测集。

06

多租户权限过滤

组织标签与用户/组织关系驱动检索与问答过滤，文档公开/私有加细粒度授权。

07

模型调用治理

按供应商熔断、舱壁隔离、指数退避重试、LLM 主备自动切换，Redis 令牌桶对关键接口限流。

08

Kafka 可靠投递

文档处理全链路走 Kafka：解析、分块、Embedding、写入 Elasticsearch，失败自动重试并进入死信队列，支持人工重放。

ARCHITECTURE

架构一览

两条主链路：文档如何变成可检索的知识，问题如何变成带引用的回答。

入库链路 · INGESTION

分片上传断点续传 · 秒传 MD5
→
解析LiteParse / Tika · PDF 保留页码
→
分块可选上下文检索
→
Embedding向量化
→
Elasticsearch索引写入

全链路由 Kafka 串联：失败自动重试，进入死信队列后支持管理员人工重放。

问答链路 · RETRIEVAL & GENERATION

WebSocket 提问流式输出 · 可主动中断
→
双路召回BM25 + KNN
→
RRF 融合可选 gte-rerank 重排
→
父子扩展小命中 · 大上下文
→
生成回答强制引用标注

检索、重排与工具调用共用请求级时间预算；多租户过滤贯穿检索全程。

TECH STACK

技术栈

与仓库 README 一致，无夸大。

后端

  • Spring Boot 3.4.2（Java 17）
  • Spring Data JPA
  • Spring Security + JWT
  • WebSocket（WebFlux）

前端

  • Vue 3.5 + TypeScript
  • Vite 6 · pnpm workspace
  • Naive UI · UnoCSS
  • Pinia · 基于 SoybeanAdmin

存储与中间件

  • MySQL 8 · Redis
  • Elasticsearch 8.10
  • Apache Kafka
  • MinIO 对象存储

AI 与解析

  • OpenAI 兼容 LLM API
  • Embedding API · 重排 API
  • Apache Tika + LiteParse
  • 可选 OCR（Tesseract / 云服务）
